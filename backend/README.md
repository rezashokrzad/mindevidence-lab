# MindEvidence Lab: Backend

This is the FastAPI backend, built on PostgreSQL with SQLAlchemy 2, Alembic, and Pydantic v2. It provides:
- **Batch 02:** a data model with 10 **fictional** teaching cases (P-001…P-010).
- **Batch 03:** a REST API, OpenAPI documentation, and frontend integration for patients.
- **Batch 04:** Google sign-in (OpenID Connect) with a backend-managed HttpOnly session cookie, CSRF protection, and per-user ownership of chat sessions.
- **Batch 05:** research-document ingestion (PyMuPDF), giving traceable chunks with section and page provenance.
- **Batches 07-09:** DeepSeek answers (modes gk/rag/both/auto), a LangGraph workflow with citation validation and safety pre-checks, an append-only audit trail with trace and activity APIs, and optional counts-only Gmail summaries. See [docs/architecture.md](../docs/architecture.md).
- **Batch 06:** semantic retrieval with pgvector (exact cosine search over embedded chunk windows), a CLI, and an evaluation script. **Needs the pgvector extension**; see [docs/retrieval.md](../docs/retrieval.md).

> All patient data is synthetic and written for teaching. It is not real people, real records, or research findings. Answers are generated by DeepSeek and checked by the backend; see [docs/architecture.md](../docs/architecture.md).

## Setup

Requirements: Python 3.11+ and PostgreSQL 16. pgvector is not needed until Batch 06.

### 1. Create a role and two databases

The test database is wiped on every test run, so its name must end in `_test`. Run these as a PostgreSQL superuser:

```bash
createuser -h localhost -U postgres --login --pwprompt mindevidence
```
```bash
createdb -h localhost -U postgres -O mindevidence mindevidence
```
```bash
createdb -h localhost -U postgres -O mindevidence mindevidence_test
```

### 2. Configure (environment only)

Copy the example file, then edit `.env`:
- set the database password in both URLs;
- set `SESSION_SECRET` (at least 32 random characters);
- set `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET`. To get them, follow **[docs/google-oauth-setup.md](../docs/google-oauth-setup.md)**.

All settings are documented in `.env.example`, and `.env` is git-ignored.

```bash
cp .env.example .env
```

Generate the session secret with:

```bash
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

### 3. Install, migrate, seed

From `backend/` (on macOS or Linux, use `.venv/bin/` instead of `.venv/Scripts/`):

```bash
python -m venv .venv
```
```bash
.venv/Scripts/python -m pip install -r requirements.txt
```
```bash
.venv/Scripts/alembic upgrade head
```
```bash
.venv/Scripts/python -m db.seed
```
```bash
.venv/Scripts/python -m app.ingestion run
```

The seed is reproducible: it reloads the synthetic case tables and never touches users, chat sessions, or documents. Research documents come from ingestion; see [Document ingestion](#document-ingestion).

### 4. Run the API

```bash
.venv/Scripts/python -m uvicorn app.main:create_app --factory --reload --port 8000
```

- Swagger UI: http://localhost:8000/api/docs
- ReDoc: http://localhost:8000/api/redoc
- OpenAPI JSON: http://localhost:8000/api/openapi.json

Then serve the frontend from the repository root and open **http://localhost:5173**. Use `localhost`, not `127.0.0.1`, so the session cookie is sent to the API:

```bash
python -m http.server 5173 --directory frontend
```

### 5. Test

```bash
.venv/Scripts/python -m pytest
```

Without `TEST_DATABASE_URL`, only the 51 tests that need no database run: seed file, auth configuration, PDF extraction, and chunking. With it, all 294 tests run, adding migrations, integrity, consistency rules, sample SQL, the API, authentication, and the ingestion pipeline. The pipeline tests include the real corpus in `data/papers`.

The auth tests never contact Google. `tests/fake_google.py` signs real RS256 ID tokens with a local key and serves the matching certificate, so `google-auth` performs its full verification offline. A real round trip through Google's consent screen needs your own credentials and was **not** tested; see the setup guide.

## Architecture

```
app/
├── main.py            create_app(): middleware, CORS, error handlers, routers
├── config.py          Settings from environment variables (pydantic-settings)
├── database.py        Engine, session factory, get_db dependency
├── security.py        Session cookie, token HMAC, signed OAuth state cookie, principal, CSRF checks
├── errors.py          Domain errors (PatientNotFound, SessionNotFound, CsrfFailed, ...)
├── integrations/
│   └── google.py      Google OIDC client: auth URL (state, nonce, PKCE), code exchange, ID-token verification
├── retrieval/         Embeddings and search (also a CLI: python -m app.retrieval)
│   ├── embedder.py    Embedder interface: sentence-transformers and a deterministic test embedder
│   ├── windows.py     Splits a chunk into overlapping windows that fit the model's input limit
│   ├── indexer.py     Batched, retried, idempotent embedding with model-mixing guards
│   ├── evaluate.py    Recall@k / MRR over data/eval/retrieval_queries.json
│   └── config.py      Embedding and retrieval settings
├── ingestion/         PDF → chunks pipeline (also a CLI: python -m app.ingestion)
│   ├── pdf_extract.py PyMuPDF extraction, quality/OCR checks, furniture removal, headings, paragraphs, metadata
│   ├── chunking.py    Paragraph- and section-aware chunker with overlap
│   ├── manifest.py    Corpus manifest validation (the allow-list)
│   ├── pipeline.py    Idempotent orchestration, failure handling, run records
│   └── storage.py     Development storage for original PDFs
├── api/
│   ├── deps.py        Validated path/query types, pagination, DB and principal dependencies
│   ├── errors.py      Exception handlers → one error envelope
│   └── routes/        health, auth, patients, documents, sessions, admin  (HTTP only)
├── services/          Business logic: existence and ownership rules, shaping responses
├── repositories/      Database access only (SQLAlchemy queries)
├── models/            ORM mappings of the tables created by migrations
└── schemas/           Pydantic request/response models (these become the OpenAPI schemas)
```

Requests flow one way: **route → service → repository → database**. Routes never query the database directly, and repositories contain no business rules.

The schema is changed only by migrations (`db/sql/*.sql`, run through Alembic). The ORM models map existing tables and never create them.

| Migration | Adds |
| --- | --- |
| `0001_cases_schema` | `cases.*` (synthetic patients) and the empty `corpus`, `auth`, `audit` schemas |
| `0002_papers_and_chat` | `corpus.papers` (catalogue), `chat.sessions`, `chat.messages` |
| `0003_auth_users` | `auth.users`, `auth.login_sessions`; `chat.sessions.owner_user_id` → `auth.users` (removes Batch 03 dev-only sessions) |
| `0004_document_ingestion` | `corpus.papers` → `corpus.documents` (+ file and provenance columns), `corpus.chunks`, `corpus.ingestion_runs` |
| `0005_embeddings` | pgvector extension, `corpus.embedding_models`, `corpus.chunk_embeddings` (`vector(384)`), `corpus.embedding_failures`. **Requires pgvector**, and stops with instructions when it is missing |

### Conventions

- **Pagination:** `limit` (1–100, default 20) and `offset` (≥ 0). Responses are `{items, total, limit, offset}`.
- **Errors:** every non-2xx response has the same shape:
  ```json
  {"error": {"code": "patient_not_found", "message": "...", "details": [], "request_id": "..."}}
  ```

| Situation | Status | `code` |
| --- | --- | --- |
| Malformed id, bad query param, invalid body, unexpected body field | 422 | `validation_error` (details list each `loc`) |
| Well-formed patient id that does not exist | 404 | `patient_not_found` |
| `POST /api/sessions` with an unknown patient | 422 | `unknown_patient` |
| Session missing **or owned by someone else** (indistinguishable on purpose) | 404 | `session_not_found` |
| Not signed in, or session expired or revoked, on a 🔒 route | 401 | `authentication_required` |
| POST without a valid `X-CSRF-Token`, or from a foreign `Origin` | 403 | `csrf_failed` |
| Student calling an `/api/admin/*` endpoint | 403 | `forbidden` |
| Unknown document or chunk id | 404 | `document_not_found` / `chunk_not_found` |
| Ingestion already running | 409 | `ingestion_in_progress` |
| No embeddings yet / pgvector missing | 503 | `retrieval_unavailable` |
| Index built by a different embedding model | 409 | `embedding_model_mismatch` |
| Embedding model cannot be loaded or run | 502 | `embedding_failed` |
| PostgreSQL unreachable | 503 | `database_unavailable` |
| Unknown route / wrong method | 404 / 405 | `not_found` / `method_not_allowed` |
| Anything unexpected | 500 | `internal_error` (no internals leaked) |

- **Request IDs:** every response carries `X-Request-ID`, echoing a valid incoming one or generating a new one. The same value appears in error bodies.
- **CORS:** only the exact origins in `CORS_ORIGINS` (default `http://localhost:5173` and `http://127.0.0.1:5173`), with credentials, `GET` and `POST`, and the headers `Content-Type`, `X-Request-ID`, and `X-CSRF-Token`. A wildcard `*` is refused at startup.

### Authentication and security model

- **Identity:** Google is the only identity provider. Users are keyed by Google's stable `sub`; email is stored and updated but is never the key. Only `openid email profile` are requested.
- **Sign-in:** server-side authorization-code flow.
  - Random `state`, `nonce`, and PKCE (S256) verifier are kept in a signed, HttpOnly, 10-minute cookie scoped to `/api/auth`.
  - The callback checks `state`, exchanges the code server to server (client secret plus PKCE), and verifies the ID token with **google-auth**: RS256 signature against Google's certificates, issuer, audience = our client id, and expiry. It then checks the `nonce`, requires `email_verified`, and applies the optional allowlists.
  - The OAuth state cookie is single-use. `return_to` is limited to `CORS_ORIGINS`, which prevents open redirects.
- **Session:**
  - A random 256-bit token lives in an HttpOnly, SameSite=Lax cookie. With `COOKIE_SECURE=true` it is also Secure and named `__Host-me_session`.
  - The database stores only `HMAC-SHA256(SESSION_SECRET, token)`. Sessions expire after `SESSION_TTL_HOURS` (default 12).
  - Sign-out revokes the row server-side. Deactivating a user (`is_active = false`) ends their sessions immediately.
- **CSRF:** POSTs need SameSite=Lax, an allowed `Origin` (or no cross-site `Sec-Fetch-Site`), and the per-session `X-CSRF-Token` from `GET /api/auth/session`.
- **Ownership:** sessions and messages are always queried with `owner_user_id = <signed-in user>`. Another user's session returns the same 404 as a missing one.
- **Secrets:** read only from environment variables (`SecretStr`, never logged; startup errors never echo values). The frontend contains no secrets, and a test checks this.
- **Production:** `APP_ENV=production` refuses to start without HTTPS URLs, `COOKIE_SECURE=true`, and Google credentials. See [docs/google-oauth-setup.md](../docs/google-oauth-setup.md#4-production-requirements-https).

## Document ingestion

Turns the authorized PDFs listed in [`data/corpus_manifest.json`](../data/corpus_manifest.json) into traceable chunks in `corpus.chunks`. No embeddings and no LLM are involved yet. The corpus itself, its licences, and its coverage gaps are described in **[docs/corpus.md](../docs/corpus.md)**.

From `backend/`:

```bash
.venv/Scripts/python -m app.ingestion check
```
```bash
.venv/Scripts/python -m app.ingestion run
```
```bash
.venv/Scripts/python -m app.ingestion show NIDA-PDAT-c0007
```

- `check` validates the manifest and the file checksums without touching the database.
- `run` ingests everything listed. Add `--force` to re-extract, or `--only ID …` to limit the run. The exit code is 0 when the run succeeds and 1 when it is partial or failed.
- `show` prints one chunk with its provenance.

Instructors can also run ingestion with `POST /api/admin/ingestion/runs`. Grant the role with `INSTRUCTOR_GOOGLE_SUBS`.

**What happens per document:**

1. The file must be listed in the manifest. If the manifest pins a `sha256`, the file must match it (`checksum_mismatch` otherwise).
2. A byte-identical copy of another document is rejected (`duplicate_file`).
3. **Idempotency:** the fingerprint is sha256(file) + pipeline version + chunk settings. If it is unchanged and the document is already ingested, nothing is written (`unchanged`). Otherwise all of the document's chunks are replaced in one transaction, so reruns never create duplicates.
4. **Quality gate:**
   - unreadable, encrypted, or empty → `failed`;
   - mostly image-only pages (scanned) → `needs_ocr`.

   Failed documents keep **no** chunks. Nothing empty is ingested silently.
5. **Extraction (PyMuPDF):**
   - drops repeated headers, footers, page numbers, and rotated edge text;
   - takes headings from the PDF outline, or from font styling when there is none;
   - builds paragraphs, merging those that continue across columns or pages;
   - records title, DOI, ISBN, and printed years found in the PDF and compares them with the manifest (`extracted_metadata`, warnings in the run report).
6. **Chunking:**
   - target 550, minimum 400, maximum 700 estimated tokens, with 80 tokens of overlap;
   - whole paragraphs where possible, and no overlap across chapters;
   - a chunk spanning subsections uses their shared section path and keeps each subsection heading in its text.
7. The original PDF is copied to `DOCUMENT_STORAGE_DIR` as `<id>-<sha12>.pdf`.
8. Chunks are stored with stable IDs `<DOCUMENT_ID>-c0001…`, section path, PDF page range, printed page labels, token count, and content hash.

Every run is recorded in `corpus.ingestion_runs` with one result per document: `ingested`, `reingested`, `unchanged`, `missing_file`, `failed`, `needs_ocr`, `checksum_mismatch`, `duplicate_file`, or `unlisted_file`. Only one run can execute at a time (PostgreSQL advisory lock).

Chunk IDs are stable as long as the file and the chunk settings stay the same. Changing either re-chunks the document and reassigns IDs deterministically. Each chunk's `content_hash` lets later batches detect that a cited chunk changed.
